# 디자인 시스템

**원칙: 차분하고, 빠르고, 도구가 주인공.** 장식보다 가독성, 화려함보다 신뢰를 우선한다. 모든 도구가 같은 손으로 만든 것처럼 보여야 한다.

## 1. 토큰

정의 위치는 `src/styles/global.css` **한 곳뿐**이다. 라이트와 다크 값이 모두 있고, `prefers-color-scheme`을 따른다.

| 토큰 (Tailwind 클래스)                                            | 용도                                                 |
| ----------------------------------------------------------------- | ---------------------------------------------------- |
| `bg-bg`                                                           | 페이지 배경                                          |
| `bg-surface`                                                      | 카드, 패널, 입력 필드 배경                           |
| `bg-surface-2`                                                    | 보조 면: 통계 박스, 비활성 트랙, 세그먼트 배경       |
| `border-line` / `border-line-strong`                              | 기본 테두리 / hover 또는 강조 테두리                 |
| `text-fg`                                                         | 본문, 제목                                           |
| `text-muted`                                                      | 보조 설명 (대비 4.5:1 이상)                          |
| `text-subtle`                                                     | 힌트, 메타 정보 (장식적 텍스트만)                    |
| `bg-accent` / `text-accent` / `bg-accent-soft` / `text-on-accent` | 주요 액션, 링크 강조, 선택 상태                      |
| `success`, `danger`, `warning` (+ `-soft`)                        | 상태 표시                                            |
| `rounded-sm/md/lg/xl`                                             | 6 / 10 / 14 / 20px                                   |
| `shadow-card` / `shadow-pop`                                      | 카드 / 떠 있는 요소                                  |
| `font-sans` / `font-mono`                                         | 시스템 폰트 스택 (CJK 포함, 웹폰트 없음 = 빠른 로딩) |

**금지:** `bg-blue-500` 같은 Tailwind 기본 팔레트, `#hex`, `rgb()`, 인라인 `style={{ color }}`. 단, 진행률 `width` 같은 동적 수치는 허용한다. 새 의미의 색이 필요하면 토큰을 추가하고 이 표를 갱신한다(라이트, 다크 둘 다).

## 3. UI 프리미티브 (`src/components/ui`)

도구 UI는 **이 컴포넌트들로만** 조립한다. 필요한 것이 없으면 여기에 범용으로 추가한 뒤 사용한다.

| 컴포넌트                | 언제                                                                                                        |
| ----------------------- | ----------------------------------------------------------------------------------------------------------- |
| `Panel`                 | 도구 전체를 감싸는 단 하나의 표면. 도구당 1개.                                                              |
| `Field`                 | 라벨, 컨트롤, 힌트 묶음. 모든 입력에 사용.                                                                  |
| `Button`                | `primary`(화면당 주요 액션 1개), `secondary`(기본), `ghost`(보조, 아이콘), `danger`. 크기는 `sm`/`md`/`lg`. |
| `CopyButton`            | 결과 복사. 복사 후 1.5초 동안 피드백 표시.                                                                  |
| `NumberInput`, `Select` | 숫자 입력, 드롭다운 (`inputClass` 공유)                                                                     |
| `Segmented`             | 옵션 2~5개 중 하나 선택 (라디오 그룹)                                                                       |
| `Toggle`                | on/off 설정                                                                                                 |
| `Dropzone`              | 파일 입력. 드래그, 클릭, 붙여넣기 지원. 파일이 있으면 `compact`.                                            |
| `Stat`                  | 결과 수치 + 라벨. 그리드로 배치. 핵심 1~2개는 `emphasis`.                                                   |
| `Notice`                | 안내, 성공, 오류 메시지                                                                                     |
| `Kbd`                   | 단축키 표시                                                                                                 |

## 4. 도구 페이지 구조 (고정)

`src/components/site/ToolPage.astro`가 모든 도구에 같은 구조를 적용한다. **도구별로 바꾸지 않는다.**

```
Breadcrumb  (홈 › 카테고리 › 도구 [› 변형])
H1 + tagline
Edge 배지   (meta.edges → "광고 없음", "브라우저에서 처리" …)
┌──────────── Panel (Tool.tsx) ────────────┐
│  입력 영역              │  설정/결과 영역 │   ← lg 이상에서 2열, 모바일은 세로 쌓기
└──────────────────────────────────────────┘
Quick presets (variants 링크)
사용 방법 → sections → FAQ (접힘) → 관련 도구 → 업데이트 날짜
```

### 도구 내부 레이아웃 패턴

- **입력 → 결과형**(글자수 세기, 변환기): `grid lg:grid-cols-[1fr_300px]`. 왼쪽에 입력, 오른쪽에 결과 `Stat` 그리드와 옵션.
- **파일 처리형**(이미지, PDF): `grid lg:grid-cols-[1fr_320px]`. 왼쪽에 `Dropzone`과 파일 목록, 오른쪽에 설정. 하단에 일괄 다운로드.
- **디스플레이형**(타이머, 시계): 중앙의 큰 디스플레이와 주요 컨트롤, `border-t`로 구분된 설정 영역, 맨 아래 단축키 안내.

## 5. 인터랙션

- 입력은 **즉시 반영**한다. 무거운 처리는 250~300ms debounce를 건다.
- 처리 중에는 해당 항목에만 "처리 중…" 상태를 보여 준다. 페이지 전체 로딩 스피너는 쓰지 않는다.
- 트랜지션은 `transition-colors` 수준으로 짧게 한다. `prefers-reduced-motion`은 전역으로 처리된다.
- 터치 타깃은 최소 32px(`h-8`)로 하고, 주요 액션은 40~48px(`md`/`lg`)로 한다.

## 6. 접근성

- 모든 입력에 라벨을 단다(`Field` 또는 `sr-only` 라벨).
- 포커스 링은 전역 `:focus-visible`이 처리한다. `outline-none`으로 지우지 않는다(대체 스타일이 있을 때만 예외).
- 실시간으로 바뀌는 결과에는 `aria-live="polite"`을 쓴다(타이머처럼 매초 바뀌는 것은 `off`).
- 색만으로 상태를 구분하지 않는다. 텍스트나 아이콘을 함께 쓴다.

## 7. 문구 (Voice & Tone)

- 짧고 구체적으로 쓴다. 동사로 시작한다("Download", "다운로드").
- 과장하지 않는다. "최고의", "혁신적인" 같은 말은 쓰지 않는다.
- 사용자를 안심시키는 사실을 먼저 말한다("파일이 업로드되지 않습니다").
- 한국어는 해요체가 아닌 **합니다체**로 쓰고, UI 라벨은 명사형으로 쓴다("초기화", "다운로드").

## 8. 아이콘

`src/components/site/Icon.astro`에 24×24 stroke 아이콘이 있다(stroke 1.75, `currentColor`). 새 아이콘은 같은 굵기로 추가한다. 이모지를 아이콘으로 쓰지 않는다.
