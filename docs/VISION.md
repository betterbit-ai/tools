# 비전과 성장 전략

## 한 줄

> **"검색하면 나오는, 업로드·가입 없는, 제일 쓰기 좋은 버전."** 이걸 사람들이 쓰는 모든 저관여 도구에 대해 만든다.

## 왜 이 모델인가

- 저관여 도구(타이머, 글자수, 이미지 크기 조절, 단위 변환…)는 **검색 수요가 영원하고**, 사용자는 **처음 클릭한 결과를 그냥 쓴다.** 한 번 상위에 오르면 트래픽이 오래 유지된다.
- 1위 사이트들은 대부분 광고, 업로드, 가입 유도로 UX가 나쁘다. 사용자 만족 신호(체류, 재방문, 북마크)로 이길 여지가 크다.
- 도구는 정적 페이지와 클라이언트 처리로 만들 수 있어서 **서버 비용이 거의 0**이다. 도구가 1,000개가 되어도 운영비는 그대로다.
- 구조가 반복적이라(`meta` + `content` + `logic` + `Tool`), **AI 에이전트가 일관된 품질로 대량 생산하기에 이상적이다.**

레퍼런스와 근거는 [COMPETITORS.md](COMPETITORS.md)에 정리했다.

## 성장 단위

```
도구 1개 = 검색 의도 1개
페이지 수 = 도구 × 로케일 × (1 + variants)
```

현재 도구 3개와 timer variants 8개가 로케일 2개로 나뉘어 도구 페이지는 22개다(홈, 카테고리 포함 시 30개). 도구 300개, 로케일 10개, 평균 variants 2개가 되면 약 9,000페이지가 된다. 모든 페이지가 실제로 다른 도구 상태를 보여 주므로 thin content가 아니다.

## 단계

| 단계               | 목표             | 내용                                                                             |
| ------------------ | ---------------- | -------------------------------------------------------------------------------- |
| **0. 기반** (완료) | 하네스           | 디자인 시스템, 레지스트리, 품질 게이트, 레퍼런스 도구 3개                        |
| **1. 핵심 50개**   | 검색량 상위 도구 | `CATALOG.md`의 P0. 이미지, PDF, 텍스트, 계산기, 변환기, 생성기                   |
| **2. 롱테일**      | 도구 300개 이상  | P1, P2 + 검색 수요가 확인된 variants                                             |
| **3. 로케일 확장** | 10개 이상 언어   | 우선순위: ja → es → pt → de → fr → id → vi → tr → it → zh-TW                     |
| **4. 습관화**      | 재방문           | 즐겨찾기 유도, PWA 오프라인, "최근 사용한 도구", 도구 간 체이닝(리사이즈 → 압축) |

## 배포 채널

1. **SEO**: 도구별 정확한 title, description, h1, FAQPage JSON-LD, 카테고리 허브와 관련 도구 내부 링크, hreflang.
2. **GEO** (LLM 인용): `llms.txt` 자동 생성, AI 크롤러 허용, FAQ 답변을 자체 완결형으로 작성(질문 없이 답만 읽어도 의미가 통하게), 수치와 근거 명시.
3. **커뮤니티 / 런칭**: 의미 있는 도구 묶음이 생기면 Product Hunt, Hacker News(Show HN), Reddit의 관련 서브레딧, 한국 커뮤니티(디스콰이엇, 긱뉴스)에 올린다.
4. **백링크**: 도구 자체가 링크받을 가치가 있게 만든다(예: 교사가 수업용 타이머로 링크). 임베드 가능한 위젯은 4단계에서 검토한다.

## 측정

- Google Search Console(로케일별 속성), Bing Webmaster Tools.
- 분석 도구는 쿠키 없는 것만 쓴다(Cloudflare Web Analytics 권장). 쿠키 배너가 필요한 도구는 쓰지 않는다.
- 도구별 KPI는 노출수, 클릭수, CTR, 평균 순위다. 노출은 많은데 CTR이 낮으면 title과 description을 고친다. 순위가 정체되면 콘텐츠와 edge를 강화한다.

## 수익화 (결정: Google AdSense, 2026-10-15)

사람이 Google AdSense로 수익화하기로 결정했다. 원칙은 다음과 같다.

- 광고는 도구 아래 콘텐츠 영역에만 둔다. 도구 영역 침범, 팝업, 전면 광고, 대기 화면은 영구히 금지한다.
- 광고 코드는 공용 레이아웃 컴포넌트 한 곳에서만 관리한다. 도구별로 광고를 넣거나 빼지 않는다.
- 도구 문구와 `edges`에서 "광고 없음"을 주장하지 않는다(`no-ads` edge는 삭제했다). 업로드 없음, 가입 없음, 속도, 정확도처럼 광고와 무관한 장점으로 이긴다.
- EEA·영국 방문자 동의는 AdSense의 Google 인증 CMP로 처리한다. 개인정보처리방침에 광고 쿠키를 명시한다.
- 나중에 고려할 수 있는 다른 선택지: 맥락에 맞는 제휴 링크, 고급 기능(대용량 배치, API) 유료화(기본 기능 제한은 하지 않는다).

**에이전트는 수익화 관련 코드(광고, 결제, 트래킹)를 임의로 추가하지 않는다.**
